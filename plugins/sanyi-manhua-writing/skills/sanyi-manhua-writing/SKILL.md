# 三义漫剧写作规则 V2.2（执行层）

> 本文件是写作线**唯一常驻规则文件**，每次写作会话加载，保持精简。
> 设计原则：**执行层做减法**——每集每稿必执行的只有"硬五条"；其余规则全部退到 `references/` 参考层，按需读取。
> **写作线零评分规则**：本文件及全部参考层只讲怎么写、怎么自查，不含任何评分模型、权重、档位或评级。评审是独立流程、独立会话、独立规则体系，不在写作会话内发生。

---

## 0. 首次使用：初始化项目

- **路径约定**：本文件提到的 `references/`、`assets/` 都指本 SKILL.md 所在目录下的子目录（Kimi Code 中即 `${KIMI_SKILL_DIR}`），不是用户项目目录；`01-设定/`、`02-状态/` 等指用户项目目录。
- 本 skill 的 `assets/项目模板/` 是项目级工作区模板。用户要开新项目、或当前目录还没有 `AGENTS.md` 与 `01-设定/` 时，先询问项目目录位置，再把 `assets/项目模板/` 的内容复制过去，不覆盖已有文件。模板里的 `AGENTS.md` 是项目说明正本，`CLAUDE.md` 只有一行 `@AGENTS.md`，两者都要复制。
- 复制后提醒用户先填 `AGENTS.md` 的"项目一句话"与"集内起伏间隔"，再填 `01-设定/` 与 `03-大纲/分集大纲.md`；未填完前不开写正文。
- `弧光预算表.md`、`悬疑信号表.md` 是可选文件，项目不需要时可删除。
- `references/金标准样例_批注格式.md` 目前是占位样例，团队应替换为内部达标剧本；替换前，只把它当格式示范，不当文风标准。

## 1. 使用边界

- **项目定位：以追剧和连播为核心，不考虑投流切片与分发。** 只考虑剧本吸引力：观众看了第一集就想继续看，一集接一集停不下来。
- 本文件用于把内容写得更好，不把每轮对话变成审稿会。用户说"评分/评审/跑分"时，停止写作模式——评审走独立流程（见 §7），写作会话内不打分、不评级、不引用任何评审标准。
- 用户指定局部范围时，只改指定范围；不得借机推翻已确认的主线、人物关系或世界观。
- 未被要求时，不输出验收报告、资产表、镜头表或流程说明。

## 2. 信息优先级与事实纪律

按以下顺序判断，高位覆盖低位：

1. 用户本轮明确要求与修改边界；
2. 当前项目唯一有效正文；
3. 项目状态文件（`02-状态/` 各表）；
4. 本规则与参考层文件；
5. 一般创作经验。

- 没有明确依据的设定、动机、能力、地点、编号、道具后果，不得擅自补完；先询问，或标为 `【待核验】`。
- 写每场前只提取"不知道就会写错"的必要事实：人物当前状态、已公开信息、能力/道具限制、未兑现承诺、场地时间、关系债。不把全量设定当成当前场的负担。
- 不把旧版本、废弃方案、其他项目的人名桥段带入本项目。

## 3. 硬五条（每集每稿必执行，其余规则都在参考层）

**H1 · 集尾追更点权重最高。**
每集结尾必须留下：新问题 / 未完成行动 / 身份揭示 / 关系决裂 / 不可逆后果，五选一以上；且下一集前段能够承接、部分兑现并升级。接不住的卡点是假钩子，等于没有。

**H2 · 每场一个可拍戏剧动作。**
每场必须能被拍成 `角色目标 → 具体阻碍 → 尝试行动 → 可见结果/局势变化`。不改变任何人物状态、关系、资源、信息或风险的场景，合并、缩短或删除。

**H3 · 开场接得住，集内有起伏。**
第 1 集开场要自己成立（谁、处于什么麻烦、观众想知道后面会怎样），不靠大段背景交代，并完成"建立 + 留住"；第 2 集起开场承接上集卡点，先回应、兑现或升级悬念，不另开无关钩子；集内按项目设定的间隔出现起伏。不设固定秒数。细则见 `references/节奏与钩子标准.md`。

**H4 · 台词干活，情绪可拍。**
关键台词至少承担一项：推进行动 / 暴露关系或秘密 / 制造冲突或逼迫选择 / 交代必要信息 / 制造反差或可回收伏笔。禁止角色互相复述已知设定、禁止讲课。情绪用动作、道具、停顿、站位承载；不写"他意识到""内心涌起"等不可拍结论。去 AI 腔细则见 `references/台词与去AI腔.md`。

**H5 · 当集必须有一个可见兑现。**
每集至少给出一个小答案、可见结果、失败后果或更大麻烦，用 `建立期待 → 可理解阻碍 → 角色尝试并承担风险 → 画面可见兑现 → 兑现带来新代价` 的结构落地。不以拖延答案伪造悬念。兑现类型与强度从 `references/情绪事件词表.md` 选取并标注。

## 4. 资产一致性（不限制创作，只统一命名）

- 场景、角色造型只引用 `01-设定/资产登记表.md` 中已登记的编号/名称/锚点串，一字不改；新资产先登记再写进剧本。
- 剧本正文不重复描述角色外貌；非默认造型在首次出场处标注版本（如"林晚（V2-病号服）"）。
- 场景数量、动作场面、群戏**不设数量上限**——剧情吸引力优先，一致性靠登记表保证，不靠删减剧情。

## 5. 每集开工与收尾流程

**开工：**
1. 读 `02-状态/下集简报.md`、`人物状态表.md`、`伏笔清单.md`；
2. 读本集在 `03-大纲/分集大纲.md` 的条目与出场人物档案；
3. 先给 5 行以内写作思路，**重点写清集尾追更点（H1）和本集主情绪事件（H5）**；写第 1 集时，另外说明如何完成"第 1 集的额外任务"（见节奏与钩子标准第二节）；确认后再写。

**收尾（写完必做，不等提醒）：**
1. 在本集备注中填写**单集开发卡**（六字段，见 `04-剧本/_模板.md`）：
   `新确认事实｜状态变化｜本集兑现（情绪事件类型+强度）｜下集承诺｜埋种/回调｜自检（H1-H5 逐条 通过/问题/修法）`；
2. 更新 `剧情摘要.md`（≤150 字）、`人物状态表.md`（只改有变化的行）、`伏笔清单.md`；
3. 补登 `资产登记表.md`（新场景、新造型版本）；
4. 覆盖重写 `下集简报.md`；
5. 列出与设定/大纲不一致之处，由用户决定是否修改，不自行改稿。

> 单集开发卡是原"冲突卡、分集事实更新卡、双轨标注、连续性快照、自检表"的合并形态——**每集只填这一张卡**，不维护多套隐性表格。自查只做"通过/问题/修法"判断，不打分。
> 长线/季度级的规划（弧光预算、世界观释放、悬疑信号回收）不进这张卡，属于立项或改季时才整体过一遍的工作，见 §8 参考层索引。

## 6. 输出方式（最小合适交付）

| 用户请求 | 默认交付 |
|---|---|
| 讨论剧情 | 直接给判断、方案与取舍 |
| 优化某场/台词 | 修改后可复制正文，只改指定范围 |
| 续写一集 | 完整剧集正文，保持已有格式与人物口吻 |
| 分集/季度大纲 | 阶段任务、每集 Logline、关键动作、情绪事件、集尾递交 |
| 立项/开新季 | 额外过一遍弧光预算与世界观释放表（见 §8） |
| 要分镜/制片包 | 写作线不产出；转独立的生产交付线处理 |
| 要自查 | 按硬五条逐条列"通过/问题/修法" |
| 要评分/评审 | 写作线不处理；转独立的评审流程 |

## 7. 边界：写作不评分

- 写作会话内不打分、不评级、不引用任何评审标准；写完的自查只列"通过/问题/修法"。
- 评审在独立会话进行，评审方只读剧本正文，不读写作思路、修改说明、设计理由等过程文件。

| 文件 | 何时读 |

| `references/台词与去AI腔.md` | 写完关键场次后自查台词时 |
| `references/情绪事件词表.md` | 设计每集兑现、规划爽点升级、填开发卡时 |
| `references/世界观释放与悬疑分层.md` | 立项/世界观重大扩展时；写悬疑、推理、身份秘密类情节时 |
